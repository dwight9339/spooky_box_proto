# In-device SD format

Date: 2026-10-01 (local time; the UTC timestamps in the log and run IDs read 2026-10-02)
Beads issue: `full_spooky_proto-jjy.14`

This session checks the optional `SD FORMAT` / `SD FORMAT CONFIRM` command on four
cards: a reference card for the confirmation guards, an unresponsive card, a used
SDHC card that is formatted and then recorded on, and an SDSC card that must be
refused.

## Results

### Confirmation guards (64 GB reference card)

- `SD FORMAT CONFIRM` without `SD FORMAT`: `ERR SD FORMAT not armed or expired`.
- `SD FORMAT`, then `SD FORMAT CONFIRM` 11.5 s later: same refusal.
- `SD STATUS` afterwards: `FREE=57576MiB`, unchanged.

### Unresponsive card (8 GB SDHC)

`SD STATUS` failed twice with `ERR SD mount failed result=FR_NOT_READY(3)
hal=0x00000000`, each after about 30 s. `SD FORMAT CONFIRM` failed the same way:
`ERR SD FORMAT failed result=FR_NOT_READY(3) hal=0x00000000 MS=37788`. The card
never reached the transfer state, so the format wrote nothing. This matches Windows,
which also cannot mount it, and the card is recorded as unusable.

Each attempt blocked the foreground for the driver's 30 s ready timeout
(`LOOP_MAX_MS=37804`). This is existing driver behavior, filed as `jjy.15`.

### Format and record (16 GB SDHC)

| Step | Result |
| --- | --- |
| `SD STATUS` before | `TYPE=SDHC/SDXC CAPACITY=15193MiB FREE=435MiB`: the Pi boot partition only |
| `SD FORMAT` + `SD FORMAT CONFIRM` | `OK SD FORMAT FAT32 CLUSTER=32768 ALIGN_SECTORS=8192 SECTORS=31116288 FREE=15189MiB MS=1998` |
| `SD STATUS` after | `FREE=15189MiB`, the whole card |
| 60 s recording (`REC000.WAV`) | `OK RECORD PASS`, exact frames, queues 1/8, max write 46 ms, histogram `0,644,57,2,1,0,0,0`, `HAS_FAULT=0`; `RECORD RESULT` matched |
| `SD STRESS 64 1` | Pass, 64 MiB written and verified, write max 58 ms, read max 10 ms, 0.5 MiB/s aggregate |
| 60 s recording immediately after (`REC001.WAV`) | `OK RECORD PASS`, queues 1/8, max write 66 ms, histogram `0,558,142,1,2,0,1,0`, `HAS_FAULT=0` |

`ALIGN_SECTORS=8192` is a 4 MiB allocation unit reported by the card. The jjy.4
SDSC card took 780-810 ms for its first write after an interrupted stress run; here
the first recording after a completed stress run peaked at 66 ms. The conditions are
not identical, and this is one used card: survey data for `jjy.8`, not a media
contract.

### SDSC refusal (2 GB SDSC)

| Step | Result |
| --- | --- |
| `SD STATUS` before | `TYPE=SDSC CAPACITY=1886MiB FREE=1807MiB` |
| `SD FORMAT` + `SD FORMAT CONFIRM` | `ERR SD FORMAT unsupported card TYPE=SDSC; SDHC/SDXC required`, immediately |
| `SD STATUS` after | `FREE=1807MiB`, mounts as before |

## Verdict

Pass: the format is guarded by a single-use 10 s confirmation, refuses SDSC and
unresponsive cards without writing, and produces an erase-block-aligned FAT32
volume that mounts and records cleanly. Only one card was formatted successfully;
broader media evidence belongs to the `jjy.8` survey.
